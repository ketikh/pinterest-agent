## Root cause (so nobody re-chases the wrong leads)
- NOT the recent-pin cache failing to persist (July hypothesis) and NOT repins
  lacking image URLs (first hypothesis today).
- The bag board and the totebag board each contain ONE pin with no `images`
  (a video/carousel pin). The old `get_random_pin` ordered candidates as
  "never-used pins only, if any exist". Once every image pin had been used
  once, the only never-used candidate was that image-less pin → ValueError →
  "No pin with a usable image URL" → orchestrator fell back to a random
  reference from the last 50 approvals → repeats forever.
- Fix: `_order_candidates` keeps used pins at the tail (LRU), and
  `get_best_image_url` handles video cover images / carousel items / all v5
  size keys. `pinterest_pin_image.py` adds a detail-call + og:image fallback
  for truly bare pins (not needed today, bare=0 after the fix).
